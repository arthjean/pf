pf ports `/home/arthur/dev/fx@1b1f9af1..9d7937d5` as a ladder of 20 contiguous first-parent slices (S1 to S20), then applies Arthur's answers in US-028. EP-001 first makes the tooling and the records able to carry the port:

Each port story (one per slice: US-005 to US-009, US-011 to US-021, and US-024 to US-027) then runs one `python3 scripts/rebrand.py port <FROM> <TO> --upstream /home/arthur/dev/fx`, where FROM is the previous slice's TO. It resolves the listed conflicts, applies the listed pf adaptations, passes the per-story gate (Linux build, Windows cross-compile, tests, `zig fmt`, rename check, public-surface audit, and a real run of `./zig-out/bin/pf`), and commits with `UPSTREAM.md` updated. PRs share a slice only when they are contiguous, need no decision, and share a test surface.

US-010, US-022, US-023, US-028 and US-029 port nothing, and a recorded skip runs no port.

The PRD decides every architecture question that is not reserved for Arthur:
- **Terminals (D-TERM option A):** pf adopts fx's in-process terminals on every OS. pf's ConPTY launcher moves inside fx's `native_session`, and Windows tty sessions end with pf like everywhere else. This supersedes the Windows PRD's US-031 and Q5. If Windows-host validation fails, Windows tty sessions are marked unsupported instead (fallback A'). Open Question Q9 flags this decision first for Arthur's review and defines the alternatives, options B and C.
- **Windows launcher directory (D-LAUNCHDIR):** launcher control sockets and bootstrap files live in `%USERPROFILE%\.pf\terminal-run`, derived from the profile and never under `%TEMP%`, and each start is checked against the 108-byte AF_UNIX path limit.
- **Shell tool text (D-SNAPUX option 3):** the shell tool schema and its digest keep fx's OS-neutral text on every OS; only the Windows `/shell reload` copy changes, with one NOTICE clause.
- **Sessions v2 (D-V2WIN option A):** v2 compiles on Windows but is refused there with an explicit message, because fx keeps v2 opt-in and a Windows port would change its crash-safety protocol. Full Windows support (option B) is a Non-Goal.
- **Public-surface audit (D-AUDIT):** the audit excludes three session manager files by path.
- **Upstream as is (D-IMAGES, D-ACP, D-GROK):** image limits, ACP defaults, and the Grok catalog follow fx.
- **SDK (D-SDK):** the libpf SDK moves in lockstep with the Zig core, because they share a wire protocol (N-API API version 3 to 4, new wasm imports). pf still does not distribute it.

The eight Stop-for-Arthur items are Open Questions Q1 to Q8. Each one has a pre-decision state (skip the slice, or hold the hunk with a pair of commits) that leaves pf's behavior unchanged, so the ladder never stalls. A recorded pre-decision skip satisfies a successor's `blocked_by` entry on the gated story, which the status file cannot express. US-028 applies the answers.

## Research Findings

Key findings that informed this PRD:

### Competitive Context
- **Electron:** keeps its changes as patch files in `patches/` and replays them on each upstream roll. Its documentation warns that a patch can break "without even a patch conflict or a compilation error", and it classifies patches as temporary, Electron-specific build changes, or functionality incompatible with upstream ([Electron patches](https://www.electronjs.org/docs/latest/development/patches)). pf differs: a divergent tree with a mechanical rename and per-range 3-way merges, so silent breakage has to be caught per slice.
- **VSCodium:** is "not a fork" but a set of scripts that build Microsoft's `vscode` repository with a community default configuration, which keeps divergence minimal by design ([VSCodium](https://github.com/VSCodium/vscodium)). pf's `rebrand.py` plays the same role for the rename, but pf also carries real feature divergence (Windows).
- **ungoogled-chromium:** refreshes a quilt series per Chromium bump, with each bump tracked in a public issue ([update issue](https://github.com/ungoogled-software/ungoogled-chromium/issues/2836)). pf records its sync point and skips in `UPSTREAM.md`.
- **Forgejo:** a fork of Gitea that switched from rebasing to weekly cherry-picks when it became a hard fork in 2024, and whose weekly cherry-picks stopped in mid 2025 because merge conflicts and dependencies on unpicked earlier changes blocked them ([forgejo/cherry-pick-tools](https://codeberg.org/forgejo/cherry-pick-tools)). pf's model is closest to this one, so cadence and ordering matter most.
- **Copybara:** transforms and moves source between repositories and stores its sync state in the destination, as a label in the commit message ([Copybara](https://github.com/google/copybara)). `rebrand.py port` is a hand-written Copybara, and this PRD adds the missing persisted state: Skipped and Held.
- **Market gap:** no tool handles "rename plus feature divergence plus upstream deletions". Mitigation is process: ordered slices, verified per slice, with recorded skips and holds.

### Best Practices Applied
- Port in small, ordered slices, verified one by one, in upstream merge order (Forgejo's failure mode, Electron's per-patch testing). Here: one slice per PR or per contiguous decision-free group, verified by sequential throwaway ports.
- Record every sync point and every skip or hold with its reason (Electron's patch provenance, ungoogled-chromium's series and issues). Here: UPSTREAM.md "Last ported", "Skipped", and "Held", and the Open Questions.
- Treat clean merges as unverified. Here: a Windows cross-compile, a real run, and named-baseline test comparisons at every slice.
- Inventory platform code before upstream deletes or rewrites a module. Here: US-021 and US-022 re-home ConPTY instead of letting the deletion merge.
- Under Apache-2.0 section 4, modified files carry notices and NOTICE is preserved ([Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0)). Here: every permanent divergence is recorded in NOTICE.
- Review imported code for services and credentials that upstream owns. Here: the Stop-for-Arthur list becomes Q1 to Q8, with pre-decision states.

## Technical Considerations

- **Architecture (terminals):** Should pf follow fx's in-process terminals (D-TERM option A), with pf's ConPTY launcher seated in `native_session` as a thread with a `KILL_ON_JOB_CLOSE` job? - **Architecture (sessions v2 on Windows):** Is a compile-only Windows build with a runtime refusal enough until fx makes v2 the default? Recommended: yes (D-V2WIN option A). It is a strict subset of full support. The `build.zig` exclusion of `run_session_manager_tests` on Windows avoids skips inside fx-owned files.
- **Data model:** fx #1062 (`/home/arthur/dev/fx@34f1ed14`) changes the v1 checkpoint format for every user (`pf-compactor-v1`, `compacted-*.txt` records), and fx #1116 (`/home/arthur/dev/fx@0107787b`) moves v2 bodies to blobs. Is the frozen d7ceb0e fixture (US-010) enough to prove backward compatibility, or should a second fixture cover a pf build with several compactions? Recommended: one d7ceb0e fixture with exactly one v1 checkpoint (US-010), which US-011's extended test resumes and compacts again in the new format; a d7ceb0e fixture with several compactions is a follow-up.
- **API design (ACP):** fx #1094 (`/home/arthur/dev/fx@d9f77663`) rejects relative `cwd` with -32602 and adds `_meta.pf.*` keys. Should pf also accept `_meta.fx.*` aliases for clients written against fx? Recommended: no alias, because no pf ACP client exists and an alias adds permanent divergence.
- **Dependencies:** No new library. The SDK lanes need Node 24 (JSPI) and Node headers, passed with `-Dnode-include-dir` when `/usr/include/node` is absent. Should US-001 record the exact Node version as part of the baseline? Recommended: yes, and US-001 records `node --version` for the Node 24 of the SDK lanes and for `/usr/bin/node`.
- **Migration:** Sessions v2 has no v1 importer in fx (`Manager.openImport` is test-only), so v1 stays the default and nothing migrates. A downgrade after EP-003 cannot read `pf-compactor-v1` checkpoints or v2 blobs. Should the CHANGELOG "Unreleased" entry state that downgrade limit? Recommended: yes for compaction checkpoints, in US-011's Context compaction entry; v2 blobs need no note, because no pf release has shipped sessions v2.
